前端接口对接文档
完整调用流程

bassUrl：http://localhost:8080

① 上传 Excel → ② 上传表结构 → ③ 创建任务 → ④ 配置映射 → ⑤ 触发生成 → ⑥ 获取结果
接口清单
① POST /api/excel/upload
上传 Excel 文件，获取 fileKey 和列头列表。

请求： multipart/form-data，字段名 file

响应：


{
  "fileKey": "a69ce3ff-...",
  "originalName": "测试数据.xlsx",
  "totalRows": 3,
  "columnHeaders": ["姓名", "年龄", "身高"]
}
注意： columnHeaders 是后续配置映射时用户选择"Excel 哪一列"的数据来源，需要渲染成下拉选项。

② POST /api/schema/upload
上传 .sql 表结构文件。

请求： multipart/form-data，字段 file + dbType（MYSQL / POSTGRESQL）

响应：


{
  "schemaKey": "f8cbc25c-...",
  "tableName": "`user`",
  "dbType": "MYSQL",
  "fields": [
    {"fieldName": "`id`", "fieldType": "BIGINT", "isPrimaryKey": true, "isNullable": false, "fieldComment": "主键ID"},
    {"fieldName": "`name`", "fieldType": "VARCHAR (50)", "isPrimaryKey": false, "isNullable": false, "fieldComment": "姓名"}
  ]
}
注意： fields 是后续配置映射的核心数据，每个 fieldName 会原样传回 /api/mapping/save，不要修改（含反引号是正常的）。

也可用 POST /api/schema/parse-string（JSON body {"ddl":"...", "dbType":"MYSQL"}）直接提交 DDL 字符串，响应格式相同。

③ POST /api/task/create
关联 Excel 和表结构，创建一次转换任务。

请求：


{
  "fileKey": "a69ce3ff-...",
  "schemaKey": "f8cbc25c-...",
  "dbType": "MYSQL",
  "batchSize": 1000
}
响应：


{
  "taskKey": "33faab8c-...",
  "status": "PENDING",
  "totalRows": 3
}
④ POST /api/mapping/save
配置每个数据库字段的赋值策略。

请求（JSON，必须 UTF-8 编码）：


{
  "taskKey": "33faab8c-...",
  "mappings": [
    {"fieldName": "`id`",          "mappingType": "SKIP"},
    {"fieldName": "`name`",        "mappingType": "EXCEL_COLUMN", "excelColumnHeader": "姓名"},
    {"fieldName": "`status`",      "mappingType": "FIXED_VALUE",  "fixedValue": "1"},
    {"fieldName": "`created_at`",  "mappingType": "FORMULA",      "formulaType": "NOW"},
    {"fieldName": "`create_time`", "mappingType": "SKIP"}
  ]
}
映射类型说明：

mappingType	额外字段	说明
SKIP	无	字段不出现在 INSERT 中
EXCEL_COLUMN	excelColumnHeader（必填）	取 Excel 对应列的值
FIXED_VALUE	fixedValue（必填）	每行都用这个固定值
FORMULA	formulaType（必填）	NOW / UUID / SEQUENCE / SNOWFLAKE_ID
注意：

所有字段必须配置，一个都不能漏（包括要跳过的，也要传 SKIP）。否则第⑤步会报"缺少映射配置"错误
excelColumnHeader 的值必须和①返回的 columnHeaders 完全一致（含中文），请求体必须 UTF-8 编码
fieldName 原样传回②返回的值，不要去掉反引号
⑤ POST /api/generate/start
触发 SQL 生成。

请求：


{"taskKey": "33faab8c-..."}
响应（小文件 ≤5000行，同步）：


{
  "taskKey": "33faab8c-...",
  "status": "COMPLETED",
  "sqlContent": "INSERT INTO `user` (`name`, `age`) VALUES\n('张三', 25);\n",
  "downloadUrl": null
}
响应（大文件 >5000行，异步）：


{
  "taskKey": "33faab8c-...",
  "status": "GENERATING",
  "sqlContent": null,
  "downloadUrl": null
}
⑥ GET /api/generate/result/{taskKey}（大文件轮询用）
每隔 2~3 秒轮询，直到 status 变为 COMPLETED 或 FAILED。


{
  "status": "COMPLETED",
  "sqlContent": null,
  "downloadUrl": "/api/generate/download/33faab8c-..."
}
⑦ GET /api/generate/download/{taskKey}（大文件下载）
直接返回 .sql 文件流，Content-Disposition: attachment，前端触发下载即可。

关键注意事项
#	事项
1	映射必须覆盖全部字段，缺少任何一个字段的映射配置，生成接口会返回业务错误
2	POST /api/mapping/save 请求体必须 UTF-8 编码，中文列头如"姓名"若以 GBK 发送会导致 500
3	totalRows ≤ 5000 同步返回 sqlContent；超出则 status=GENERATING，需走轮询+下载流程
4	fieldName 含反引号（MySQL）或双引号（PostgreSQL）是正常现象，原样传回即可，不要做处理
5	所有接口统一响应格式：{"code":200,"message":"操作成功","data":{...}}，code≠200 时取 message 展示给用户
